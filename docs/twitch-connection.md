# Twitch接続の復旧動作

## コンパネの表示

認証済みのアカウントと、コメント受信用EventSubの接続状態を別々に表示する。

| 状態 | 動作 |
| --- | --- |
| コメント受信の準備中 | WebSocketを開き、イベントの購読を登録する |
| 接続正常 | コメントの購読が有効になり、接続を監視している |
| 再接続中 | 自動で復旧を試みる。「今すぐ再接続」で待機を省略できる |
| 再認証が必要 | 「再認証する」からTwitchの認証をやり直す |
| 接続を開始できません | 購読が拒否された状態。「今すぐ再接続」で再試行できる |

Raid・Bits・サブスク・モデレーション同期の購読に失敗した場合は、該当する通知を警告し、コメントの受信を継続する。これらの購読は次回の接続時に再登録するため、復旧を試す場合は「今すぐ再接続」を使用する。

## 接続管理

- 切断・通信エラー・keepaliveの欠落を検知し、自動で再接続する。
- 待機時間は約1、2、4、8、16、30秒と増やし、最大30秒に小さなランダム時間を加える。60秒以上接続が続いたら待機段階をリセットする。
- 通常の再接続では新しいセッションへ購読を登録し直す。
- Twitchから`session_reconnect`を受けた場合は、指定URLをそのまま使用する。新しいWelcomeを受け取るまで旧接続で受信し、購読を引き継ぐ。
- 通知IDを10分間・最大10,000件保持し、再接続やトークン更新をまたぐ二重表示を抑止する。ログアウト時に履歴を消す。
- Raidのプロフィール・クリップ取得を別の処理へ分離し、その待ち時間中もコメント、keepalive、Ping/Pongを処理する。
- ログアウトや接続のやり直しで古い処理を終了し、古い接続状態が画面へ反映されることを防ぐ。

## 制約と確認方法

Twitchは通常の切断中に発生したイベントを再送しないため、その間のコメントや通知を復元することはできない。接続正常の表示はコメントが実際に投稿されたことを意味しない。

自動テストではローカルWebSocketサーバーで切断、無通信、Ping応答、購読待機、接続先の切り替え、重複通知、購読の取り消しを再現する。画面の状態変更、再接続・再認証操作、起動時の認証再試行も確認する。

実際のTwitchアカウント・OBSでの確認は別途必要。配信前に接続し、コメント表示、通信切断からの復旧、Raid紹介中のコメント受信、アプリ再起動後の復元を確認する。

仕様の参照先: [Twitch — Handling WebSocket Events](https://dev.twitch.tv/docs/eventsub/handling-websocket-events/)、[WebSocket Reference](https://dev.twitch.tv/docs/eventsub/websocket-reference/)。
