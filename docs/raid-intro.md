# Raid紹介

[日本語](raid-intro.md) | [English](raid-intro.en.md)

Raid紹介には自動紹介と手動紹介があります。どちらもコンパネの「Raidクリップ設定」で、イントロ時間、クリップ再生、本数、シャウトアウトの使用有無を設定します。

## 共通設定

| 設定 | 自動紹介 | 手動紹介 |
| --- | --- | --- |
| イントロ表示 | 設定時間だけ自動表示 | 設定時間だけ自動表示 |
| クリップ再生 | イントロ後に自動実行 | レイダーごとのボタンから実行 |
| 再生本数 | 設定した最大本数 | 設定した最大本数 |
| シャウトアウト | クリップ終了後に自動実行 | レイダーごとのボタンから実行 |

Raidを受信した時点の設定が、そのレイダーの紹介処理に使用されます。

## 自動紹介

Raidを受信すると、設定に従って次の順序で実行します。

1. Raid元ユーザーのプロフィール画像、表示名、Raid人数を表示する
2. クリップ再生が有効なら、Twitch Clips APIから取得したクリップを設定本数まで再生する
3. シャウトアウトが有効なら、クリップ終了後にTwitch Shoutout APIでRaid元ユーザーをシャウトアウトする
4. 紹介処理を終了し、次のRaidを処理する

クリップを取得できなかった場合はクリップ処理を飛ばし、シャウトアウトへ進みます。

## 手動紹介

手動紹介でもイントロまでは自動で表示します。イントロ終了後は、Raid元ユーザーごとの操作カードをコンパネへ追加します。

カードには、設定と取得結果に応じて次の項目を表示します。

- Raid元ユーザーのプロフィール画像、表示名、ログイン名、Raid人数
- 「クリップを再生」ボタン
- 「シャウトアウト」ボタン
- カードを終了する`×`ボタン

クリップとシャウトアウトは、どちらから先に実行しても構いません。有効な操作が両方完了するとカードは自動で閉じます。

### 操作例

- クリップを再生してからシャウトアウトする
- 配信者が口頭で紹介し、シャウトアウトだけ実行して`×`で閉じる
- クリップだけ再生して`×`で閉じる
- どちらも実行せず`×`で閉じる

クリップ再生要求は通常のRaid表示と同じキューへ追加されます。別のRaidイントロや手動クリップと重ならず、受け付けた順番に再生します。再生中または待機中は、同じカードから再度クリップを要求できません。

クリップが取得できなかったカードには、その旨を表示します。シャウトアウトに失敗した場合はカードを残すため、原因を解消してから再実行できます。

## シャウトアウトの制限

Twitch Shoutout APIには次の制限があります。

- チャンネル全体で2分に1回
- 同じ配信者には60分に1回

アプリ内で成功した自動・手動シャウトアウトから制限時間を記録します。手動カードでは残り秒数を表示し、既知の制限時間中はAPIを呼び出しません。

アプリを再起動した場合や、Twitch・別ツールからシャウトアウトした場合の制限状態は引き継げないため、TwitchからHTTP 429が返る場合があります。その場合は制限時間が終わってから再実行してください。

## クリップ再生

- Twitchから取得した各クリップの実時間を使用します
- 取得したクリップのうち、設定した最大本数まで再生します
- 配布環境で安定して自動再生するため、クリップは常にミュートです
- 手動で再生したクリップもOBS用オーバーレイに表示されます

## 設定の互換性

旧形式の`portable-data/config/overlay.json`は、初回読み込み時に現在の既定値へ移行されます。移行後にコンパネで保存した設定は維持されます。
